# 📈 AStock AI Tracker (A股 24H 全自动实战幕僚系统)

> **跑在你 NAS 上的永不休眠交易大脑：不测风云，只做应对。**
> *A 24/7 self-tracking A-share trading copilot, running headless on your NAS.*

## 🌟 前言：它是什么？

绝大多数 AI 炒股工具，是"你问它才答"的聊天机器人。但真实的 A 股战场是 **7×24 小时不间断**的：凌晨 3 点的美股收盘、盘中某一刻的跳水异动、盘后的减持公告、深夜的行业政策——人类根本无法全天候盯盘。

**本项目是一个原生部署在 NAS（如 fnOS / Synology）上的 24 小时全自动自选股持续跟踪器。**
它像一个永不休眠的专属交易员，长驻在你的家用服务器后台：
- 它 **24 小时自动轮询自选股池**，从盘前的宏观消息、盘中的异动拉升，到盘后的龙虎榜、深夜的公司公告，全天候全自动追踪；
- 它 **不依赖任何"你主动来问"的交互**——所有情报由它在后台抓、在后台算、在后台推，你只需要在微信上看结果；
- 它 **依托 Hindsight 长期记忆**，记住每只股票逐渐沉淀出来的"股性"和你设定的操作纪律；
- 它 **绝不输出"建议关注"这类废话**，而是把情报全部转译成**条件触发式（If-Then）操作剧本**：每天早晨一看推送，你就知道每一档价格该挂什么单。

## 🎯 解决三个真实痛点

| 痛点 | 本项目的答案 |
|---|---|
| **单点崩溃**：一个接口挂了全盘停摆 | 腾讯为主源 + 东财为备源的纯程序双源比对，数据不符即熔断告警，**绝不发未校验数据**；消息源（财联社/智通/巨潮）独立于行情源，互不牵连 |
| **消息过载**：7×24 电报几万条，看不过来 | LLM 噪声过滤器只做一件事：**这则消息和我自选股池有没有关系**。无关的直接丢弃，相关的必须回答"它意味着什么、我该怎么做" |
| **建议模糊**：AI 说"中线偏好、逢低吸纳"，没法执行 | 输出强制结构化：`消息定性 → 记忆提醒 → 三套 If-Then 剧本`，每个剧本绑定一个明确的价格触发线和动作 |

## 🏗️ 核心架构（数据怎么抓、怎么算、怎么发）

```text
                        ┌──────────────────────────────────────────────┐
                        │           NAS (fnOS)  常驻后台               │
                        │                                              │
  行情源(量价)          │  ┌─────────────┐    ┌──────────────────┐     │
  腾讯 qt.gtimg.cn ────┼─▶│ Python 纯计算 │───▶│  质检门禁         │     │
  东财 push2 API   ────┼─▶│ (算MA/量比/  │    │ 双源比对+末根日期 │     │
                        │  │  支撑压力)  │    │ 断言, 不过则熔断  │     │
  消息源(7x24/公告)     │  └─────────────┘    └────────┬─────────┘     │
  财联社/智通 7x24  ───┼─▶   大模型(LLM) 只做两件事：                     │
  巨潮资讯 公告    ────┼─▶   ① 消息降噪+定性  ② 推演/复盘               │
  行业研报/热榜    ────┼─▶                                    │         │
                        │  ┌──────────────────┐               │         │
  记忆库 Hindsight ◀───┼─▶│  Hindsight (NAS本地) │◀──────────────┘         │
  (股性/纪律/教训)      │  │  只存规律, 不存价格  │                        │
                        │  └──────────────────┘                        │
                        │        Hermes Cron (08:45 / 盘中 / 15:30 /    │
                        │         21:00 / 23:00)  ── hermes send ──────┼──▶ 你的微信
                        └──────────────────────────────────────────────┘
```

**四条铁律：**
1. **数字全部由程序计算**：K线、MA5/10/20、量比、支撑/压力位由 Python 硬算，AI 只读不算，杜绝模型幻觉数字。
2. **质检门禁**：腾讯与东财最新价差 > 0.05 元、K线末根日期 ≠ 最近已收盘交易日、开高低出现非正值——任一命中即熔断，只发"质检失败告警"，不发行情。
3. **记忆隔离**：带日期的价格（今天的收盘价）**绝不写入**长期记忆；Hindsight 只沉淀"股性规律、支撑位有效性、失败教训"，防止日后把旧价当当前事实召回。
4. **LLM 链路解耦**：`--no-agent` 模式下脚本直出结果、`hermes send` 原文投递（退出码 0/1/2 可判定是否真的发出去），模型只参与"推演/复盘/反思"三个增值环节，不在数据搬运链路上。

## 📡 消息获取与展示机制（重点）

### A. 消息从哪来？三类源、三条独立管道

| 消息类别 | 数据源 | 抓取方式 | 频率 |
|---|---|---|---|
| **盘中 7×24 电报** | 财联社电报 / 智通财经 / 东财 7x24 快讯 | HTTP API 增量拉取（记录上次阅读游标，只取新增） | 交易时段每 30 分钟静默扫一次 |
| **盘后/深夜公告** | 巨潮资讯网（官方指定披露渠道）/ 新浪财经公告 | 按自选股代码逐个查询当日公告列表 | 21:00 整批扫描 |
| **行业与资金面** | 东财行业板块资金流 / 同花顺热榜 / 研报评级 | HTTP API | 盘前 08:45 汇总 |

> 行情（量价）与消息（舆情）是**两条互不依赖的管道**：行情源挂了，公告照样能推；消息源挂了，K线质检照样跑。避免"一条链路断、全盘哑火"。

### B. 消息怎么处理？LLM 噪声过滤器

7×24 电报一天上万条，99% 与你的自选股无关。过滤器只做三件事：
1. **相关性判定**：这条消息是否直接命中自选股池（公司名/股票代码/所属细分行业）？→ 不命中，直接丢弃；
2. **定性打分**：利好 / 利空 / 中性，置信度如何？
3. **转译成行动**：这条消息**改变今天哪个剧本**？（例如：盘前已给"冲高 53.5 减仓"剧本，盘中突发利好 → 剧本动态修正为"三分钟内站稳则暂缓卖出"。）

### C. 消息怎么展示？微信端统一版式

所有推送（无论盘前/盘中/盘后）共用同一个结构，**信息密度拉满、废话清零**：

> 🚨 **[盘中异动] 13:15 · 中际旭创 (300308)**
> 📰 **情报**：[偏多] 某部委发布算力基础设施新政（7x24电报 13:02 抓取，已核实原文）
> 📊 **盘面**：现价 902.4 ｜ 已突破早盘推演的 895.9 压力线 ｜ 量比 1.4 ｜ 出现 3 笔万手大单
> 🧠 **记忆提醒**：该股历史上政策利好首日冲高回落概率 70%（来自 2 次历史同类事件）
> 🎯 **剧本修正**：
> - 若 3 分钟内站稳 905 → 暂缓卖出，观察是否加速；
> - 若冲高 930 附近放量滞涨 → 立刻按原计划高抛底仓；
> - 若利好不及预期快速回落至 895 下方 → 剧本 3（防守）接管。

## ⏱️ 24 小时全天候运转时间轴

系统通过 Hermes 原生 Cron 在 NAS 后台静默调度，**无需任何人工触发**：

### 🌅 08:45 盘前推演 —— 带着剧本开盘
1. 汇总昨夜 21:00 至今晨的全部相关消息 + 美股/港股相关标的隔夜表现；
2. 从 Hindsight 调取该股票的股性画像（"遇利空习惯早盘诱多下杀"、"20 日线历次支撑有效"等）；
3. 结合你的仓位画像，生成**三套 If-Then 剧本**推送微信：
   > 📅 **[盘前推演] 08:45 · 中际旭创 (300308)**
   > 📰 **隔夜情报**：[偏空] 美股光通信板块昨夜收跌 2.3%
   > 🧠 **股性记忆**：该股板块利空日习惯 9:40 前恐慌下杀，20 日线（约 852）承接较强
   > 🎯 **今日剧本**：
   > - 🟢 急跌至 852 附近且分时企稳 → 用可用现金买入，博弈日内反弹做 T
   > - 🔴 逆势冲高至 930 压力带且量比 <1 → 高抛底仓
   > - ⚫ 半小时内跌破 835 不回头 → 放弃买入计划，防守观望

### ⚡ 09:30–15:00 盘中看门狗 —— 无事静默，有事秒推
- 每 30 分钟静默扫描一次 7×24 电报 + 盘口异动（放量、急拉、急跌阈值）；
- **空输出即静默**（`--no-agent` 机制，stdout 为空 = 不推送），不打扰你；
- 只有触发阈值（命中自选股的重大消息 / 价格异动）才推送盘中告警，并**动态修正当日剧本**。

### 🌇 15:30 盘后对账 —— 预测 vs 真实，残酷打分
1. 拉取当日真实收盘 K 线、量比、资金流向；
2. AI 将"盘前剧本"与"真实走势"逐条对账：
   > 📊 **[盘后对账] 15:30 · 中际旭创 (300308)**
   > 📝 **实际**：最高 899.2，未触及 930 压力带；尾盘随板块回落，收 895.86（-2.89%）
   > 🔍 **偏差诊断**：剧本 1（急跌买入）未触发——实际最低 884.1，高于 852 触发线；剧本 2（高抛）未触发。大盘单边下行拖累，量比 0.8 说明主力无意拉升
   > ✅ **今日执行质量**：按剧本未动 = 正确（剧本没触发就不该动）

### 🌌 21:00 晚间公告扫描 —— 拦截"第二天开盘才知道"的雷
- 逐只扫描巨潮公告（业绩预告 / 股东减持 / 中标 / 诉讼）；
- 命中 → 推送定性提醒："明日开盘前必读：XX 发布减持公告，注意高开/低开应对"；
- 无命中 → 静默。

### 🧠 23:00 深夜反思与记忆进化 —— 让系统越用越懂
- LLM 在后台总结当日复盘，**剥离所有价格数字**，只提取规律；
- 写入 Hindsight（`stock_tracking` bank），示例：
  > "【股性规律】中际旭创在缩量（量比<0.8）日，突破 20 日均线的成功率低，次日早盘不可做突破预期，应提前在压力带下方挂单；"
  > "【策略修正】大盘单边下行日，个股支撑触发线应整体下移 1.5% 再观察，避免接飞刀。"
- **该任务本地静默运行（deliver local），不推送任何消息。**

一周后你的记忆库就有了带时间戳的股性画像；一个月后，这个系统的盘前推演质量将显著超过人工盯盘。

## 🛠️ 从零搭建：五个具体步骤（NAS / fnOS）

**前提**：NAS 上已装好 Hermes Agent，已配置大模型 API（任意支持 OpenAI 协议/Vertex 的模型），微信推送通道（WeChat）已登录连通。

### 步骤 1：配置自选股池与用户画像（唯一需要手动的配置）
在 `config/watchlist.json` 中声明自选股与操作纪律（**不写任何具体成本/股数也能跑**，写了则剧本更贴合你）：
```json
{
  "stocks": ["sz300308", "sh688256"],
  "style": "重仓防守型：严禁建议追高加仓；只允许基于可用现金做日内 T；所有输出必须为 If-Then 条件剧本"
}
```
> 不写持仓明细，系统默认按"空仓观察者"模式运行，只做信号提示；写入明细后自动切换"持仓操作"模式。

### 步骤 2：部署三个核心脚本
放入 `~/.hermes/scripts/`（Cron `--script` 只认这个目录）：
- `fetch_market.py` — 纯计算层：腾讯主源 + 东财备源，算 MA/量比/支撑压力，双源比对 + 末根 K 线日期断言，输出标准化 JSON；
- `fetch_news.py` — 消息层：7×24 电报增量拉取 + 巨潮公告扫描，输出结构化情报；
- `strategy.py` — 推演层：读取上面两层的 JSON + Hindsight 记忆 + 自选股配置，调用 LLM 生成 If-Then 剧本 / 复盘 / 反思（这是唯一调用模型的地方）。

### 步骤 3：初始化 Hindsight 记忆库
确认 NAS 上的 Hindsight 容器在跑（`curl 127.0.0.1:8888/v1/default/banks` 能列出 `stock_tracking` 库），并把 `watchlist.json` 的 `style` 字段作为首条"操作纪律"写入。此后每日 23:00 的反思会自动积累。

### 步骤 4：配置五档 Cron 调度
```bash
# 盘前推演（走 LLM 推演，直发微信）
hermes cron create --name "astock_盘前推演" \
  --script strategy.py --deliver weixin:<你的openid> \
  --model <固定模型> --provider <固定provider> --schedule "45 8 * * 1-5"

# 盘中看门狗（纯脚本，无模型；空输出=静默；stdout 非空才推送）
hermes cron create --name "astock_盘中监控" --no-agent \
  --script fetch_news.py --deliver weixin:<你的openid> \
  --schedule "*/30 9-14 * * 1-5"

# 盘后对账（走 LLM 复盘，直发微信）
hermes cron create --name "astock_盘后对账" \
  --script strategy.py --model <固定模型> --provider <固定provider> \
  --deliver weixin:<你的openid> --schedule "30 15 * * 1-5"

# 晚间公告（纯脚本，无命中则静默）
hermes cron create --name "astock_晚间公告" --no-agent \
  --script fetch_news.py --deliver weixin:<你的openid> \
  --schedule "0 21 * * 1-5"

# 深夜记忆进化（本地静默，不推送）
hermes cron create --name "astock_记忆进化" \
  --script strategy.py --deliver local --schedule "0 23 * * 1-5"
```
> 两个防呆点：① 显式 `--model/--provider` 固定模型，防止平台默认模型变动导致任务被静默跳过；② `--no-agent` 任务（盘中/晚间）空 stdout 自动静默，天然实现"无事不打扰"。

### 步骤 5：试运行与验收
1. 手动各跑一次：`python3 ~/.hermes/scripts/strategy.py morning` 等，确认微信收到三条版式正确的推送；
2. 手动触发一次 `hermes cron run <job_id>`，确认 Cron 通道投递成功（`hermes send` 退出码为 0）；
3. 周一 08:45 起放手让它自己跑，连续 5 个交易日观察：盘前剧本是否结构完整、盘中是否只在真异动时推送、23:00 记忆库 `fact_count` 是否按日增长（`curl 127.0.0.1:8888/v1/default/banks`）。
4. **验收标准**：连续 5 个交易日 ① 无一次"假质检通过"、② 无一条无 If-Then 结构的推送、③ 无一次推送失败不可见。

## 📐 设计边界（本项目明确不做什么）

- **不预测点位和日期**——只给条件框架与参考线；
- **不替你下单**——所有动作需要你手动执行，系统只负责让你"知道此刻该挂什么单"；
- **不存行情快照进长期记忆**——价格只在当天的推演上下文里存在一次；
- **不承诺收益**——它的价值是纪律、信息差反应速度和认知复盘，不是印钞机。
